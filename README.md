# GM3323D 鼠标灯控（MouseLight）

一个极轻量、常驻系统托盘的**用户态**鼠标灯光 + 电量控制工具，用于替代原厂驱动里的灯光设置功能。

- 目标设备：**VID 0x1D57 / PID 0xFA60**（Windows 设备管理器里名称含 `GM3323D`）
- 协议来源：对原厂软件行为的**实测差分**，详见 [`docs/protocol.md`](docs/protocol.md)
- 技术栈：C++17 + Win32 + 原生 HID API（SetupAPI / `HidD_*`），无第三方库、无 .NET/MFC/Qt、无控制台窗口
- 资源占用：空闲 CPU ≈ 0%、内存 < 5 MB（电量监听走阻塞 `ReadFile`，无轮询）

## 1. 功能

| 功能 | 说明 |
|---|---|
| 开灯 / 关灯 | 关灯 = 下发灯效模式 `00`（原厂 `Off`） |
| 颜色 | 任意 RGB，托盘图标同步染成当前颜色 |
| 亮度 | 1–8 档（与原厂滑块一致） |
| 灯效模式 | 8 种已命名模式（另有 2 个原厂未命名模式值，按"不编造"原则未列入） |
| 电量显示 | 托盘电池图标实时显示电量百分比（详见第 6 节协议说明） |
| 配置保存 | 存于 `HKCU\Software\GM3323DLight`，启动时自动恢复 |
| 开机自启 | 写入 `HKCU\...\Run`，可随时开关 |
| 插拔处理 | `WM_DEVICECHANGE`，重连后自动重新下发配置 |
| 单实例 | 系统互斥量；重复双击会直接唤出已有实例的设置窗口（不弹提示框） |
| 恢复默认 | 一键关灯 + 复位，防止灯卡在异常状态 |

> 应用 / 保存后**不会弹出任何提示框**——鼠标灯光本身的变化就是反馈。

## 2. 构建

双击 **`build.bat`**，或在命令行执行：

```
build.bat
```

脚本会自动探测并按顺序选择编译器：

1. **MinGW-w64 `g++`**（PATH 中，或常见安装位置：WinLibs / MSYS2 / w64devkit）
2. **LLVM-MinGW `clang++`**
3. **MSVC `cl.exe`**（需从 "x64 Native Tools Command Prompt for VS" 运行）

产物：`dist\MouseLight.exe`，Release x64，GUI 子系统（无控制台）。

### 静态 vs 动态运行库

| 方式 | 体积 | 依赖 |
|---|---|---|
| **静态（默认，推荐）** | **约 290 KB**（含图标资源） | 无，单文件即可运行 |
| 动态 | 约 90 KB | 需 `libstdc++-6.dll` / `libgcc_s_seh-1.dll` / `libwinpthread-1.dll` |

切换方式：编辑 `build.bat`，把 `-static` 去掉即变为动态链接。默认选静态，是为了保证单文件可运行、不依赖任何运行时。

清理：双击 **`clean.bat`** 删除全部构建产物与中间文件。

## 3. 使用

1. 双击 `MouseLight.exe`，系统托盘出现彩色图标（颜色 = 当前灯光颜色）。
2. **右键**图标弹出菜单：

```
开灯
关灯
────────────
选择颜色 ▸        自定义颜色...
灯效模式 ▸        关灯 / 固定色 / 呼吸 / 霓虹 / 循环呼吸 /
                 固定色-随DPI / 呼吸-随DPI / 流光 / 跑马灯
亮度 ▸            1 档 ~ 8 档
────────────
设置...
开机自启            (勾选即开启)
恢复默认 / 关闭灯光
────────────
写入格式: 原样(默认)   ← 仅排错用，见第 5 节
────────────
退出
```

3. 选完颜色/模式/亮度后配置会立即保存，下次开机自动恢复。
4. **双击**图标打开设置窗口（颜色 + 灯效 + 亮度 + 应用/保存）。
5. 托盘图标显示一个电池，中间的数字是电量百分比；鼠标未连接时显示 `?`。

## 4. 开机自启

菜单中点击「开机自启」即可切换，写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，**不需要管理员权限**，也**不会**写 `HKLM`。

## 5. 卸载

1. 托盘右键 → 「恢复默认 / 关闭灯光」（可选，让鼠标回到关灯状态）。
2. 托盘右键 → 「退出」。
3. 菜单里关闭「开机自启」。
4. 删除 `MouseLight.exe`。
5. （可选）删除配置：`reg delete HKCU\Software\GM3323DLight`。

卸载后鼠标保持关灯前的状态；重新插拔或断电后由鼠标固件自身恢复默认。

## 6. 风险说明与已知限制

- **只匹配 VID 0x1D57 / PID 0xFA60**，绝不会向其它 USB 设备写入任何数据。
- **不会**修改/刷写固件、不写内核驱动、不注入其它进程、不采集或上传任何数据。
- 写入前先 `GetFeature` 读回当前 132 字节配置，**只修改其中 5 个已确认含义的字节**（模式/亮度/R/G/B），其余 127 字节原样回写，避免破坏未知字段。
- **电量**走另一条通道（UsagePage `0x000A` 的 5 字节 Input 报告 `03 00 40 01 07`），`[4]` = 0..10 档 → ×10 = 百分比。**目前为单点校准（70% 吻合）**，若你观察到不同电量下百分比偏差较大，只需调整 `ParseBattery()` 中的映射即可，不影响其它功能。
- **呼吸速度**：原厂 UI 有 1–8 的呼吸速度滑块，但实测采集时从未产生变化，**字节位置未能确认，因此未实现**（不编造）。
- **未列入 UI 的 2 个模式值**（`0x09` / `0x0a`）：确实存在且有效，但原厂语言文件中没有对应名称。
- **「写入格式」开关**：本设备对 `GetFeature(0x04)` 的回应首字节是数据 `0x05` 而非报告 ID `0x04`（不符合 HID 规范），因此写入时首字节该填哪个存在二义性。默认「原样」已实测可用；若你的设备无反应，可切换为「报告ID前缀」再试，**无需重新编译**。
- 若设置颜色后无效果，用「恢复默认 / 关闭灯光」即可一键熄灭，不会让灯卡在异常状态。

## 10. 技术流（如何逆向出这套协议）

把一台"杂牌 / OEM 贴牌"鼠标的灯光、电量乃至 DPI 做成**用户态**工具，核心难点不是"写 HID 栈"，而是**抓包反推协议，找到那几个有意义的字节**。完整工作流如下：

### Phase 0 — 确认设备
- 从设备管理器或 `HidD_GetAttributes` 拿到 **VID/PID** 与设备名。
- 确认它是 **HID** 设备（不是自定义 USB class），后续全部基于 HID API；非 HID 设备应尽早提示。

### Phase 1 — 摸清 HID 拓扑（先做这步，能避免卡死）
- 枚举所有 device interface，逐个取 `HIDP_CAPS`，记录 `UsagePage`、`FeatureReportByteLength`、`InputReportByteLength`。
- 典型拓扑（GM3323D 实测）：

  | 集合 | UsagePage | Feature | Input | 角色 |
  |------|-----------|---------|-------|------|
  | col#0 | 0x000A | — | 5B | 电池 / 监控 |
  | col#1 | 0x000B | 132B | — | 灯光 / 配置 |
  | col#2 | 0x0001 | — | 2B | 标准鼠标 |
  | col#3 | 0x000C | — | 3B | 媒体键 |

- **关键坑**：只有 `FeatureReportByteLength > 0` 的集合才接受 `HidD_GetFeature`；对**没有 feature 的集合**调用它会**永久阻塞**线程，必须把每次调用用 **200ms 超时线程**包起来。

### Phase 2 — 抓包反推协议（真正的难点）
- 用一个扫描探针（见 `tools/` 与本仓库附带的 `hid_probe`）枚举目标 VID/PID 的所有集合，对每个带 feature 的集合扫描 report ID 1..63，并用**超时绑定的 `GetFeature`** 抓"连贯状态"，同时用阻塞 `ReadFile` 抓 Input 报告。
- 运行方式：用户退出本工具（避免独占句柄）→ 打开原厂驱动停在对应页面 → 跑探针 → **在抓取窗口期间**操作鼠标设置（如把 DPI 从最小拖到最大再拖回 2~3 次）→ 生成日志。
- 三条血泪经验（不要重蹈覆辙）：
  1. **配置态是瞬时的**：连贯配置块（如灯光 `05 0d …`）只在原厂软件写入的**那一瞬间**出现，独立句柄被动轮询（哪怕 10ms）几乎抓到 0 命中。必须在"操作的同时"广而快地扫描多个 report ID 才能逮住。
  2. **绝大多数 feature 读取是 flash 噪声**（高熵随机内存），只认固定签名（`05 0d`、`04 32 01 08` …）和结构化低熵块，其余忽略。
  3. **电量几乎都是 Input 报告**（UsagePage `0x000A`），用阻塞 `ReadFile` 读，不是 `GetFeature`。

### Phase 3 — 搭应用
- 以 `src/main.cpp` 为骨架：改 `kVID/kPID`、`kReportID`、`kFeatLen`、签名、`kModes`，把抓到的 132 字节填进模板，把发现的偏移映射到 `OFF_*` 与 `ApplyConfig()` 写路径。
- 写策略：**先 `GetFeature` 读回 → 只改已确认含义的字节 → `SetFeature` 回写**，绝不覆盖未知字节，避免把设置写崩。

### Phase 4 — 验证与发布
- 跑 exe，确认鼠标对每个控制有反应、托盘电量刷新；某控制无反应时，切换"写入格式"开关（部分固件首字节要报告 ID，部分要原始数据字节）。
- `.gitignore` 排除 `dist/`、`build/`、`*.exe`；源码 + 文档上 GitHub，exe 作为 `dist/` 附件随仓库发布。
- 本仓库还包含一个 `skill` 分支，存放可复用的 **offbrand-mouse-driver** 技能（通用探针 + 方法论 + 应用骨架），可用于为任意杂牌鼠标复刻本流程。

## 11. 关键技术实现要点

- **技术栈**：C++17 + Win32 + 原生 HID（`setupapi.h` / `hidsdi.h` / `hidpi.h`），无 .NET / MFC / Qt，无控制台（`-mwindows`），静态链接（`-static`）单文件约 290KB。
- **单实例**：命名互斥量 + 一个隐藏顶层窗口（`WS_EX_TOOLWINDOW`）接收 `WM_DEVICECHANGE` 与跨实例唤醒消息。
- **零 CPU 空闲**：电量走阻塞 `ReadFile` 子线程，插拔走 `WM_DEVICECHANGE`，稳态无定时器、无轮询循环。
- **动态电池图标**：用 `BITMAPV5HEADER` 在内存里画电池 + 百分比，经 `CreateIconIndirect` 注入托盘，颜色随当前灯色变化。
- **配置持久化**：`HKCU\Software\GM3323DLight` 存模式 / 亮度 / 颜色 / 自启；自启写 `HKCU\...\Run`，无需管理员、不碰 HKLM。
- **安全边界**：只匹配 VID 0x1D57 / PID 0xFA60，绝不对其它 USB 设备写数据；不刷固件、不写内核驱动、不注入进程、不上传数据。
- **构建坑**：`windres` 需 `--use-temp-file`；`.bat` 必须纯 ASCII（中文在 GBK 控制台会乱码导致命令静默失败）。
- **协议不确定性处理**：呼吸速度字节未确认就不实现（不编造）；未命名模式值（`0x09` / `0x0a`）因无对应名称不列入 UI；电量 `[4]` 为单点校准（70% 吻合），偏差大时只改 `ParseBattery()` 映射。
- **写入格式开关**：本设备对 `GetFeature(0x04)` 的回应当首字节是数据 `0x05` 而非报告 ID `0x04`（不符合 HID 规范），故写入首字节该填什么存在二义性；默认"原样"实测可用，无反应时可切"报告 ID 前缀"再试，**无需重新编译**。
