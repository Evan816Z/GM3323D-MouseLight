# GM3323D 协议映射表（实测）

> 所有结论均来自对原厂软件行为的**外部实测差分**，未反编译、未复制任何原厂代码。
> 目标设备：**VID 0x1D57 / PID 0xFA60**（设备名 `GM3323D`）。

---

## 1. HID 拓扑

通过 SetupAPI 枚举 + `HidP_GetCaps` 读取 UsagePage，设备暴露 4 个集合（collection）：

| 集合 | UsagePage | 能力 | 用途 |
|------|-----------|------|------|
| #0 | `0x000A` | Input 5 字节 | **电量监听**（`Open_DevMonitor` 通道） |
| #1 | `0x000B` | **Feature 132 字节** | **灯光/配置**（唯一带 Feature 的集合） |
| #2 | `0x0001` | Input 2 字节 | 标准鼠标 |
| #3 | `0x000C` | Input 3 字节 | 媒体 / Consumer |

- 灯光配置只存在于 **#1（UP 0x000B）**；其下 `rid 0x04` 起多个报告 ID 均回显同一份 132 字节配置，忽略 rid 号，固定用 `0x04`。
- 电量走 **#0（UP 0x000A）** 的 Input 报告，与灯光通道完全独立。

---

## 2. 灯光配置（Feature 报告）

- 读取：`HidD_GetFeature(handle, buf, 132)`，首字节填报告 ID `0x04`。
- 设备会交替返回多种"人格"（固件/随机内存块）。只认签名 **`05 0D`** 的配置态：
  - `[0] == 0x05`（`kSig0`）
  - `[1] == 0x0D`（`kSig1`）
- 配置态只在**设备状态变化瞬间**短暂出现，因此需要重试（代码内 `ReadConfig` 重试 24 次、间隔 60 ms）。

### 已确认字段

| 偏移 | 字段 | 取值 |
|------|------|------|
| `[0]` | 签名 | `0x05` |
| `[1]` | 长度标记 | `0x0D` |
| `[3]` | 灯效模式 | `0x00`=关灯(Off)；`0x01`..`0x08` 见下表；`0x09/0x0A` 有效但未命名 |
| `[5]` | 亮度 | `0x01`–`0x08`（1–8 档） |
| `[6]` | R | 0–255 |
| `[7]` | G | 0–255 |
| `[8]` | B | 0–255 |

### 灯效模式表（已命名）

| 值 | 名称 |
|----|------|
| `0x00` | 关灯 (Off) |
| `0x01` | 固定色 (Static) |
| `0x02` | 呼吸 (Breathing) |
| `0x03` | 霓虹 (Neon) |
| `0x04` | 循环呼吸 (Cycle Breathing) |
| `0x05` | 固定色-随DPI (Static DPI) |
| `0x06` | 呼吸-随DPI (Breathing DPI) |
| `0x07` | 流光 (Wave) |
| `0x08` | 跑马灯 (Marquee) |

> `0x09` / `0x0A`：实测有效但原厂语言文件中无名称，按"不编造"原则未列入 UI。

### 写入策略（read-modify-write）

写入前先读回当前 132 字节配置，只改上述 5 个字节，其余 127 字节原样回写，避免破坏未知字段。若读不到有效配置态，则回落到内置的**真实设备模板**（`kDefaultTemplate`，同样只改那 5 个字节）。

### 写入首字节二义性

本设备对 `GetFeature(0x04)` 的回应首字节是数据 `0x05` 而非报告 ID `0x04`（不符合 HID 规范），因此 `SetFeature` 时首字节该填哪个存在二义性：

- `kWriteRaw`（默认，**已实测可用**）：首字节直接下发数据 `0x05`。
- `kWriteIDFirst`：首字节放报告 ID `0x04`，数据整体后移 1 位。

两者均已实现，可通过托盘菜单「写入格式」实时切换，**无需重新编译**。

## 3. 电量（Input 报告）

- 监听集合 #0（UP `0x000A`），阻塞 `ReadFile`（约 2.9 s/条），空闲 CPU = 0。
- 报告示例（21 次采样全部一致）：`03 00 40 01 07`

| 字节 | 含义（推测） |
|------|------|
| `[0]` | 报告类型 `0x03` |
| `[2]` | `0x40` 疑似电压 / 原始 ADC |
| `[3]` | `0x01` 疑似充电标志 |
| `[4]` | 电量档位 `0..10` → **×10 = 百分比**（例：`0x07` → 70%，与原厂读取吻合） |

> ⚠ **单点校准**：仅以 70% 一个点验证。若你观察到不同电量下百分比偏差较大，只需调整 `ParseBattery()` 中 `[4]*10` 的映射（例如改为分档表），不影响其它功能。

## 4. 实测未确认 / 未实现

| 项 | 状态 | 说明 |
|----|------|------|
| 呼吸速度 | 未实现 | 原厂 UI 有 1–8 滑块，但采集时从不变化，字节位置未知 |
| 回报率（return rate） | 观察到变化、未暴露 | `config_dump` 中 `[24]` 字节在切换回报率时由 `03`→`02` 变化，编码未坐实，且非用户核心需求，故未接入 UI |
| DPI | **已移除** | 原厂 DPI 设置经多轮探针未能在可读配置块中稳定定位（配置态只在变化瞬间出现，独立句柄轮询捕获率≈0）；按用户决定已从本项目移除，仅保留灯光 + 电量 |

---

## 5. 安全约束

- 仅匹配 VID/PID，**绝不向其它 USB 设备写任何数据**。
- 不刷写固件、不写内核驱动、不注入进程、不上传数据。
- 所有写操作均为 read-modify-write，只动已确认字段。
